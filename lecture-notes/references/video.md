# 视频转 Obsidian 笔记

适用：一场 15–60 分钟的讲座/分享录像，固定机位或轻微移动，画面里有幻灯片和讲者。

目标：一条视频 → 一篇可独立阅读的图文长文（章节时间戳 + 20–30 张不重复幻灯片，口播融进正文）。

## 0. 先看视频

```bash
ffprobe -v error -show_entries format=duration,size \
  -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,sample_rate,channels \
  -of default=noprint_wrappers=1 "<video>"
```

记下：时长、分辨率、帧率、音轨。1080p60 的 30 分钟视频约 3–5 GB，不要整段读进内存。

## 1. 抽音频与转写

```bash
ffmpeg -i "<video>" -vn -ac 1 -ar 16000 -c:a pcm_s16le "$WORK/audio.wav"
bash scripts/transcribe.sh "$WORK/audio.wav" "$WORK/asr" zh
```

- 中文场用 `zh`；英文场用 `en`；不确定用 `auto`。
- **默认 turbo**。实测 17 分钟中文分享，large-v3 只改了 3 句，还把「UI 还原」整句丢了；turbo 更完整、快一个量级。
- 超过 30 分钟建议按 15 分钟切段，段间留 30 秒重叠，避免长上下文漂移；合并时去掉重叠处的重复句。

## 2. 选关键帧：不要用场景硬切

幻灯片常用淡入淡出、局部动画，`select='gt(scene,0.25)'` 只能抓到少数硬切，会漏页。

用「每 2 秒采样 + 512 位感知哈希 + 稳定帧聚类」：

```bash
python3 scripts/video_prepare.py "<video>" --out "$WORK/video"
# 先试 10 分钟：--start 0 --end 600
```

17 分钟测试片实际输出 36 张，其中 35 张是分享页、1 张是片尾装饰卡；用 `--end` 截到最后一句发言即可去掉片尾。

脚本内部：

1. `fps=1/2` 采样，缩到 33×16 灰度。
2. **只哈希画面上部**（默认前 760px），排除讲者走动造成的假变化。
3. 33×16 生成 512 位 dHash；与「当前稳定帧」比较，距离 > 70 视为换页。
4. 等画面连续两帧稳定（相邻距离 ≤ 17）后再取帧，避免抓到转场中间态。
5. 用全分辨率重新抽帧，输出 `keyframes/`、`times.txt`、`keyframes.json`。

经验值：

| 视频长度 | 候选帧 | 去重后入笔记 |
| --- | ---: | ---: |
| 15–20 分钟 | 30–40 | 20–25 |
| 30 分钟 | 60–70 | 25–35 |
| 45–60 分钟 | 90–120 | 30–40 |

**不要用 9×8 / 64 位哈希**：灰底小字页之间只差 9 位，会把 HTML 页和相邻页判成同一张。512 位才分得开。

## 3. OCR：全帧，不要裁底部

```bash
python3 scripts/ocr_images.py \
  --src "$WORK/video/keyframes" --out "$WORK/video/ocr" \
  --strict --max-side 1920 --restart-every 0
```

关键：

- **用全帧 1920px**。幻灯片内容会延伸到画面底部 930–1000px，裁到 880 会把结论句、页脚、来源整行切掉。
- `--strict` 使用「逐字输出、不要概括、不要遗漏底部小字」提示词；普通照片仍用默认提示词。
- 视频帧通常 30–70 张，连续跑更稳；若同时有别的本地模型任务，显式 `--restart-every 0`。
- 普通幻灯片 13–22 秒/张；代码编辑器截图可能 100 秒/张，且 OCR 全是 `<?php` 噪声。代码截图默认跳过。

## 4. 按标题去重

```bash
python3 scripts/dedupe_slides.py --src "$WORK/video/ocr" --out "$WORK/video/slides.json"
```

规则：

- 去掉 MXC/IxDC/Experience Center 等页眉页脚。
- 取第一行有效文字作为标题；标题相似度 ≥ 0.82 视为同一页。
- 同一标题保留 OCR 文字最长的一张（文字最全）。
- 代码截图标记 `kind: code`，默认排除。
- 输出 `slides.json`：`file`、`time`、`title`、`chars`、`kind`、`excerpt`。

**只把 `slides.json` 和最终选中的 20–30 张图读进在线上下文**，不要回读全部 OCR 原文。这是控制 token 的关键。

## 5. 写笔记

- 文件名：`NN-<主题>-<讲者>.md`。
- 元信息加视频时长、分辨率、讲者身份。
- **默认写图文长文**：正文按演讲顺序分节，每节给 `[hh:mm:ss]` 时间戳；图片嵌在对应段落后，不设末尾幻灯片库。
- 图片 20–30 张，全部内嵌；每张图注写「它证明了什么」，不要写「现场照片」。
- 正文按 7–9 个章节组织，口播、图片、判断写在同一节；保留讲者原意，不补没说的观点，也不另附整理稿。
- 总览只放场次地图和跨场洞察，不重复单场图片。

## 6. 时间与 token 预算

30 分钟 1080p60 视频，M5 Pro 64GB 实测估算：

| 阶段 | 时间 |
| --- | --- |
| 抽音频 + ASR | 2–4 分钟 |
| 选帧 + 抽全帧 | 2–3 分钟 |
| OCR 60–70 张 | 15–25 分钟 |
| 去重 + 写笔记 | 5–10 分钟 |
| 合计 | 25–40 分钟 |

Token 控制：

- 不要把 35–70 份 OCR 原文、contact sheet、PDF 预览反复读进上下文。
- 本地先生成 `slides.json`，在线只读这一份 + 选中的图。
- 探索性实验交给子 agent，或把中间结果写文件后只读摘要。
- 这批 17 分钟视频全流程在线用量约 1499 万 token（纯写笔记阶段约 719 万），其中 99.4% 是缓存读取；优化后 30 分钟视频目标 300–500 万。

## 7. 已知边界

- 固定机位效果最好；手持/走动镜头会产生更多假切换，需要提高阈值或先做稳定处理。
- 讲者会挡住底部少量文字；全帧 OCR 能救回大部分，被身体完全遮住的字无法还原。
- ASR 对专业名词不稳定：B 端→「弊端」、UI 还原→「女朋友还原」、上下文→「上下分」、裁判员→「财产员」。必须用 OCR 标题和上下文交叉校验。
- 同传/双语场仍按 `references/pipeline.md` 的同传规则处理。
- 代码截图、终端截图不适合做图注；保留一张作为「真实代码」证据即可，不要每张都 OCR。

## 8. 圆桌 / panel 专用流程

适用：多人固定座位、一个主题大屏、没有逐页幻灯片；文件名常带「圆桌 / panel / 论坛」。

```bash
python3 scripts/video_prepare.py "<视频>" --out "$WORK/video" --panel --frame-at 2
```

- **只抽 1 张现场图**。优先开场页：屏幕有主题/主持人，画面能看到所有嘉宾。换题页可以补，但不要做成幻灯片画廊。
- 音频照常走 `transcribe.sh`；多段视频分别转写，时间轴写「第一段 00:00 / 第二段 00:00」。
-  OCR 只作为辅助：读屏幕上的主题、主持人、姓名条；不要把圆桌帧当幻灯片逐页 OCR。
- **先确认人，再提炼观点**：
  1. 看开场自我介绍，记下姓名、公司、职位。
  2. 用官方日程/活动页交叉校验。IXDC 的英文页常只给拼音，中文名要再用报道/搜索确认。
  3. 确认不了时，用「XX 公司 / XX 行业 / 主持人」标注，并在笔记里写「身份未完全确认」。
- 说话人归属优先用「内容线索」：谁做国际化、谁做 B 端安全、谁做麦当劳数字产品、谁做微软设计。不要凭声音猜。
- 输出结构：发言人备注表 → 按议题的观点 → 1 张现场图 → 附「发言纪要」（按时间/议题，不是逐字稿）。
- 圆桌的「金句」只保留能确认出处的短句；无法确认就写成「现场大意」，不要伪造原话。
- 参考案例：2026 IXDC B4「AI Workflow 重构设计团队的工作方式」，59 分钟主讨论 + 10 分钟收尾，4 位嘉宾 + 1 位画外主持，最终只保留 1 张开场图。
