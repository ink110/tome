# 完整工作流

> 这份文件是 `tome-portrait` 的执行手册。SKILL.md 只给骨架；具体命令、子代理提示词、判断标准都在这里。

## 目录与命名

```text
<项目目录>/
├── 00-收集/
│   ├── <前缀>001：<主题>.md          # 蒸馏稿
│   ├── <前缀>001：<主题>_raw.txt     # 原始字幕（不改）
│   ├── <前缀>001：<主题>_meta.json   # 元信息（含播放/点赞/收藏等）
│   ├── _manifest.json                # 清单（manifest.py 生成）
│   └── _coverage.md                  # 覆盖度报告
├── 00-收集-外部/
│   └── <人物>·外部001：<主题>.md
├── 10-画像/
│   ├── _调研/
│   │   └── <人物>·调研001-016.md
│   ├── _调研-外部/
│   │   ├── A-他者·争议.md
│   │   ├── B-他者·成就.md
│   │   ├── C-著作与长文.md
│   │   ├── D-时间线.md
│   │   ├── E-对话与访谈.md
│   │   ├── F-决策与行为.md
│   │   ├── G-对比参照系.md
│   │   ├── H-言行漂移.md
│   │   └── I-失败与被证伪.md
│   ├── <人物>·思维操作系统2.0.md
│   └── <人物>·核验表.md
├── 20-输出/
│   ├── <人物>·思维操作系统2.0（全书）.md
│   ├── 案例索引.md
│   ├── 金句索引.md
│   └── <人物>·传播案例库.md / 选题清单.md
└── _meta/progress.md
```

命名规则：

- 一手：`<前缀><NNN>：<主题>.md`，`NNN` 三位补零，前缀默认取合集名（清洗掉书名号、空格、非法字符）。
- 外部：`<人物>·外部<NNN>：<主题>.md`，编号连续。
- 调研分片：`<人物>·调研<起>-<止>.md`。
- 画像版本只增不改：`2.0`、`2.1`……旧版本不覆盖。

## 第 0 步：初始化

```bash
python3 ~/.claude/skills/tome-portrait/scripts/new_project.py \
  --person "<人物>" \
  --root "<信息源根目录>" \
  --collection "https://www.bilibili.com/video/BVxxxx/"
```

不给 `--root` 时，项目目录由共享配置决定：folder 模式落到 `<信息源根目录>/<人物>`，obsidian 模式落到 `<Obsidian库>/topics/<人物>`。给了 `--root` 则在 `<root>/<人物>` 下建。

脚本会建目录、写 `_meta/progress.md`、写一个空的 `_meta/project.json`（人物、链接、前缀、开始日期）。已有文件不覆盖；要重来加 `--force`。

## 第 1 步：采集主信息源

### 1a. 全量落原文（快，先拿到底稿和元数据）

```bash
python3 ~/.claude/skills/tome-bili/crawl_collection.py "<合集里任意一个 BV 或链接>" \
  --out "<项目>/00-收集" \
  --prefix "<前缀>" \
  --raw-only
```

- 这一步只抓字幕 + 元信息，不调模型；137 集约几分钟到十几分钟。
- 无 AI 字幕的集，脚本会失败；记下集号，用 `tome-bili/references/asr.md` 的 faster-whisper 方案补。
- 断点续跑：已存在的 `_raw.txt` 会跳过。

### 1b. 生成清单和覆盖度

```bash
python3 ~/.claude/skills/tome-bili/manifest.py \
  --dir "<项目>/00-收集" \
  --out "<项目>/00-收集/_manifest.json" \
  --coverage "<项目>/00-收集/_coverage.md"
```

清单字段：集号、BV、标题、发布日期、时长、播放/点赞/投币/收藏/评论/转发、有无字幕、是否 ASR、是否重复、源链接。覆盖度报告给年份分布、缺号、重复标题、无字幕集、播放分布。

### 1c. 本地模型蒸馏（慢，分批跑）

```bash
python3 ~/.claude/skills/tome-bili/crawl_collection.py "<BV>" \
  --out "<项目>/00-收集" \
  --prefix "<前缀>" \
  --distill-only \
  --start-ep 1 --end-ep 20
```

- 单集约 6 分钟（qwen2.5:32b）；按 20 集一批，后台跑，跑完检查。
- 已存在的成品 md 自动跳过；失败的单集重跑即可。
- 蒸馏稿固定体例：核心观点速览 / 分节正文 / 案例速查表 / 金句摘录 / 学习记录 / 附：完整口播稿。

> 顺序很重要：先 raw-only，再生成清单，再蒸馏。这样来源地图不用等十几个小时，缺口判断可以提前做。

## 第 2 步：来源地图

读 `_manifest.json`、`_coverage.md` 和标题列表，写 `<项目>/10-画像/来源地图.md`。模板见 `references/source-map.md`。

必须回答四个问题：

1. 这套语料覆盖了哪些年份、主题、场合？
2. 哪些年份 / 主题 / 场合明显缺失？
3. 哪些内容是重复的、标题党式的、或只有结论没有案例的？
4. 外部要补什么，优先级怎么排？

**判断原则**：博主的合集代表博主的选材偏好，不是这个人的完整公开表达。缺号不等于没发生，只等于这套合集里没有。不要把「合集里没有」写成「他没做过」。

## G1：人工确认补充范围

只给用户看三样：

- 来源地图的一页摘要（覆盖了什么、缺什么）
- 补充清单（按优先级，最多 10 条）
- 预计工作量（本地蒸馏还剩多少集、外部要搜几轮）

用户确认后继续；用户说「先这样」就跳过外部补充，直接进入分片调研，并在画像的「诚实边界」里写明。

## 第 3 步：补外部材料

### 搜索维度（nuwa 六维 + 三个补充维）

| 文件 | 维度 | 搜什么 |
|---|---|---|
| A | 他者·争议 | `<人物> 争议`、`起诉`、`监管`、`批评`、`质疑`、`诉讼` |
| B | 他者·成就 | `<人物> 融资`、`合作`、`排名`、`获奖`、`纪录` |
| C | 著作与长文 | `<人物> 白皮书`、`公开信`、`书`、`长文`、`博客` |
| D | 时间线 | `<人物> 年表`、`大事记`、`2016`…`2026` |
| E | 对话与访谈 | `<人物> 访谈`、`播客`、`对谈`、`专访`、`问答` |
| F | 决策与行为 | `<人物> 收购`、`投资`、`人事`、`产品`、`链上动作` |
| G | 对比参照系 | `<人物> vs <同行>`、`竞争对手`、`同赛道` |
| H | 言行漂移 | `<人物> 早期`、`后来`、`改口`、`立场变化` |
| I | 失败与被证伪 | `<人物> 失败`、`项目失败`、`被驳回`、`被分叉`、`下架` |

### 外部文件体例

```markdown
# <人物>·外部001：<事件 / 主题>
> 一句话摘要

## 核心事实速览
- 【司法/官方】事实描述（✅实锤）[URL]
- 【权威媒体】事实描述（🔶指控）[URL]

## 分节正文
（还原场景、时间、人物、因果链；区分「谁说的」和「发生了什么」）

## 案例速查表
| 事件 | 一句话 | 支撑什么 | 来源 |
| --- | --- | --- | --- |

## 关键引语
> 「逐字引语」——<说话人>，<场合>，<日期>，[URL]

## 学习记录
- 事实：
- 证据强度：
- 对画像的意义：
- 存疑点：

---
## 附：完整原始材料（来源 + URL + 强度）
## 未证实清单
- ❓ 某说法只出现在单一二手来源，未找到原始文件。
```

### 铁律

- 每条外部事实必须有：来源层级、强度、URL、日期。
- 起诉 ≠ 定罪；和解 ≠ 认罪；指控 ≠ 事实。
- 单一二手来源的说法只能写「有报道称」，不能写成事实。
- 找不到原始文件时，写进「未证实清单」，不要删掉线索。
- 同一事件有多个说法时，把冲突并列，标出哪一方证据更强。

### 子代理提示词（外部维度）

```text
你在做「<人物>」的外部核验，负责维度：<A 他者·争议>。

任务：
1. 用 WebSearch 搜 6–10 个高质量来源，优先原始文件、权威媒体、行业媒体。
2. 按下面的体例写一个 Markdown 文件：
   <粘贴上面的外部文件体例>
3. 每条事实标来源层级 + 强度 + URL + 日期。
4. 区分「指控」「和解」「判决」「媒体报道」「传闻」。
5. 文末必须写「未证实清单」。
6. 不要复述人物自己的说法当事实；他的自述只能作为「他说的」出现。

输出到：<项目>/10-画像/_调研-外部/A-他者·争议.md
只输出文件，不要在对话里重复全文。
```

并行 4–6 个维度；不要一次开十几个，容易限流。

### 把调研笔记汇总成书稿

`10-画像/_调研-外部/` 里的是原料，不是书稿。每个值得进书的事件/主题，合并成一篇：

```text
<项目>/00-收集-外部/<人物>·外部NNN：<主题>.md
```

- 一个文件只讲一个事件/主题；同一事件的多个来源合并，冲突并列。
- 编号从 `001` 起，三位补零；文件名必须含 `外部NNN：`，成书脚本靠这个识别。
- 保留「核心事实速览 / 分节正文 / 案例速查表 / 关键引语 / 学习记录 / 附：完整原始材料 / 未证实清单」。
- 不要把所有维度塞进一篇；也不要一个来源一篇。

## 第 4 步：分片调研

### 切片

- 每片 12–16 集，按集号连续切；不要按主题切（会丢失时间线）。
- 一片一个文件：`10-画像/_调研/<人物>·调研001-016.md`。
- 137 集约 9–11 片。

### 每片的 8 节固定体例

```markdown
# <人物>·调研 001–016

## 1. 核心论点
- [T-候选] 一句话论点（集号 + 时间戳 + 原话）
- 复现次数：本片 N 次；跨片待合并

## 2. 自创术语
| 术语 | 他的定义 | 首次出现 | 用法 |
| --- | --- | --- | --- |

## 3. 心智模型候选
- 模型名：
  - 公式 / 一句话：
  - 适用场景：
  - 反例 / 失效场景：
  - 证据：集号 + 时间戳

## 4. 决策启发式
- 如果……就……（集号 + 时间戳）

## 5. 表达特征
- 句式：
- 比喻：
- 情绪：
- 禁忌 / 回避：
- 高频词：

## 6. 具体案例
| 案例 | 一句话故事 | 支撑什么 | 集号 / 时间戳 |
| --- | --- | --- | --- |

## 7. 失败与矛盾
- 他说的 vs 他做的：
- 前后不一致：
- 被外部证伪：
- 本片内无法判断：

## 8. 时间线线索
- YYYY-MM：事件（集号）
```

### 子代理提示词（分片）

```text
你在做「<人物>」的分片调研，负责第 <起>–<止> 集。

输入：
- 蒸馏稿：<项目>/00-收集/<前缀><起>：*.md 到 <前缀><止>：*.md
- 原始字幕：同名 _raw.txt（用于核对原话）

任务：
1. 逐集读蒸馏稿；需要核对原话时读 _raw.txt。
2. 按 8 节固定体例输出（见下）。
3. 每个论点、案例、金句都带集号 + 时间戳；没有时间戳的，写「集号，无时间戳」。
4. 不要跨片合并；不要下最终结论；只做本片的证据提炼。
5. 区分「他说的」和「外部可查证的」；本片只有他本人语料时，外部栏写「待核验」。
6. 不确定的标 ❓，不要编。

输出到：<项目>/10-画像/_调研/<人物>·调研<起>-<止>.md
只输出文件。
```

并行 4–6 片。每片完成后检查：8 节是否齐、有没有集号和时间戳、有没有把结论写成事实。

## 第 5 步：综合画像

读全部 `_调研/` + `_调研-外部/`，写 `10-画像/<人物>·思维操作系统2.0.md`。

### 5.1 分类

默认 6 类（可按人物调整，保持 6 类结构）：

1. 关于钱与投资
2. 关于选择与职业
3. 关于关系与边界
4. 关于规则与风险
5. 关于内容与表达
6. 关于自我与叙事

每类 4–6 条，总数 26–36 条。每条一个稳定 ID：`T01`…`T36`。

### 5.2 四道验证

一个候选只有同时过前两道，才进入画像；后两道决定它的权重和置信度。

1. **跨域复现**：在至少 3 个不同年份 / 场合 / 话题里出现。
2. **生成力**：能对一个新的、他没直接谈过的场景给出可检验的判断。
3. **排他性**：不是「努力就会成功」这种放之四海皆准的话；能看出是他这个人的镜片。
4. **外部行为验证**：能解释或预测他后来的真实行为（来自 `_调研-外部/`）。

被外部行为证伪的，不要删；独立成条，标 `⚠️ 反面案例`，并写清「他说的」和「他做的」的差距。

### 5.3 每条的四段式

严格按 `references/portrait-spec.md`：

```markdown
### 01 · <一句话标题>

**背景**
（当时的场景、处境、面对谁、为什么说）

**观点**
（他的原话 / 原模型；引用用「」）

**案例**
（当时他怎么讲 + 后来真做了什么；外部事实带来源标记）

**AI 经验**
（唯一专门为用户写的可迁移经验）

置信度：★★★
```

### 5.4 其它固定章节

- 画像性质说明
- 人物画像标签（最硬的可迁移技能）
- 核心心智模型（6–10 个，含公式、适用场景、失效场景）
- 决策启发式速查表（8–12 条）
- 表达 DNA
- 时间线（树结构，降序）
- 价值观与反模式
- 内在张力
- 失败清单
- 诚实边界（必填）
- 调研来源
- 附录 A–E

### 5.5 写入前检查

- 每条都有 ID、四段、置信度。
- 每类都有导读，不直接跳到条目。
- 时间线是树结构，不是平铺表格。
- 引语按原字幕分行，行尾两个空格。
- 没有 `『』`、没有 `（【】）`、没有句中加粗。
- 反面案例独立成条并标 `⚠️`。

## G2：人工确认画像结构

只给用户看：

- 6 类的名称和每类条数
- 全部条目标题（一行一条）
- 3 条完整样例（不同类别，含反面案例）
- 诚实边界

不要贴 6 万字全文。用户确认分类、条目、语气后，再写书。

## 第 6 步：核验

按 `references/verify.md`：

1. 每条结论打 3 星（言行一致 / 可核验数据 / 具体案例或独立来源）。
2. 写 `10-画像/<人物>·核验表.md`：条目 ID、结论、证据、星级、矛盾点。
3. 对每条核心结论做一次反证搜索：`<人物> + <结论关键词> + 反例 / 失败 / 批评`。
4. 把矛盾清单同步进画像的附录 B 和「诚实边界」。
5. 找不到反例时写「未找到反例」，不要写「证明成立」。

## 第 7 步：成书

按 `references/book.md`：

1. 没有封面就先生成：
   ```bash
   python3 ~/.claude/skills/tome-book/scripts/make_cover.py \
     --title "<人物>·思维操作系统 2.0" \
     --subtitle "<一句话副标题>" \
     --author "<人物> 口述" \
     --out "<媒体根>/cover.png"   # obsidian: <库根>/eagle-cache/articles/<人物>/cover.png；folder: <项目>/assets/cover.png
   ```
2. 一条命令同时产出 md 和 epub：
   ```bash
   python3 ~/.claude/skills/tome-portrait/scripts/make_book.py \
     --project "<项目>" \
     --subtitle "<一句话副标题>" \
     --cover "<媒体根>/cover.png"
   ```
   产出：
   - `20-输出/<人物>·思维操作系统2.0（全书）.md`
   - `<输出目录>/<人物>·思维操作系统2.0（阅读版）.epub`
3. 生成 `20-输出/案例索引.md` 和 `金句索引.md`。
4. 跑 `tome-book/scripts/validate.py`，0 XML 错误、0 失效链接、0 表格残留。

书的固定结构见 `references/book.md`。md 和 epub 内容必须一致。

**微信文章项目**：`00-收集/` 是文章标题，`make_book.py` 的自动识别会漏掉全部文章。先按 `tome-book/references/wechat-book.md` staging，再用 `build_book.py --config` 构建。

## 第 8 步：传播复盘（可选）

调用 `tome-spread` skill。

**有播放 / 互动数据时**（B 站等）：

```bash
python3 ~/.claude/skills/tome-spread/scripts/rank.py \
  --manifest "<项目>/00-收集/_manifest.json" \
  --top 20 \
  --out "<项目>/20-输出/_候选传播案例.md"
```

**平台不公开互动数时**（微信公众号等）：跳过 `rank.py`，按 `tome-spread/references/selection.md` 的四项代理指标筛选——站内回引、站外转载、引用跨度、独家材料，至少满足三项。不要估算阅读量。

产出 8–12 个案例、10–15 个选题、3–5 个内容结构模板，分别作为第三篇、附录 F、附录 G 加进书。案例和选题里的链接必须取 `_manifest.json` 的 `source_url`，不要用「下一篇」链接或自己拼接。

## G3：最终验收

- 画像：6 类、条数、每条四段、置信度、附录 A–E 齐。
- 核验表：每条有星级、矛盾点、反证结果。
- 书：封面、扉页、篇章页齐全；正文章节 = 1 总纲 + N 一手 + M 外部 + K 案例 + 1 附录 F + 1 附录 G（没有的项不计）；nav 三层，附录 F/G 在顶层。
