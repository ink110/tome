# 成书

> 一本书，两种格式：Obsidian 里的合并 md（检索版）+ 微信读书里的 epub（通读版）。
> 内容必须一致；区别只在排版和交互，不在信息量。

## 一、书的固定结构

```text
封面
扉页（书名 / 副标题 / 定位 / 作者·整理者 / 版本 / 开始阅读）
总纲（画像：6 类 + 人物标签 + 心智模型 + 表达 DNA + 时间线 + 附录 A–E）
第一篇 · 逐集案例（每集一篇）
第二篇 · 外部素材（每篇一个事件 / 主题）
第三篇 · 传播案例（可选，8–12 篇）
附录 F · 选题清单（可选，10–15 条）
附录 G · 内容结构模板（可选，3–5 个）
```

- 总纲就是 `10-画像/<人物>·思维操作系统2.0.md`，在书里标题改成 `000 · 总纲：……`。
- 第一篇的每篇对应 `00-收集/` 的一个蒸馏稿。
- 第二篇的每篇对应 `00-收集-外部/` 的一个文件。
- 第三篇来自 `tome-spread` skill 的 `传播案例库.md`；每篇一个 H1。
- 附录 F 来自 `选题清单.md`；一篇一章。
- 附录 G 来自 `内容结构模板.md`；一个 H1（附录标题），模板用 H2。附录 F、G 都必须是顶层目录项，不能嵌进第三篇。

## 二、每篇的固定小节

### 第一篇 · 逐集案例

```markdown
# 001 · <主题>

> 原视频：[BVxxxx](https://www.bilibili.com/video/BVxxxx/)

## 核心观点速览
## 分节正文
## 案例速查表
## 金句摘录
## 学习记录
## 附：原文口播稿
```

- 原视频链接指向视频页即可，不需要精确到时间戳。
- 口播稿在阅读版里按约 300 字分段、每段只留开头一个时间戳；归档版保留完整时间戳。
- 每篇的 H1 用 `NNN · 主题`，不要用文件名。

### 第二篇 · 外部素材

```markdown
# 外部素材 01 · <事件 / 主题>

## 核心事实速览
## 分节正文
## 案例速查表
## 关键引语
## 学习记录
## 附：完整原始材料（来源 + URL + 强度）
```

- 每条外部事实带来源层级 + 强度 + URL。
- 文末带「未证实清单」。

### 第三篇 · 传播案例

```markdown
# S01 · <标题>

## 传播数据
## 为什么传播
## 钩子
## 结构拆解
## 故事模板
## 证据
## 可复用点
## 我的改编
## 边界
```

- 微信等不公开互动数的平台，`## 传播数据` 写代理指标（站内回引、站外转载、引用跨度、独家材料），不要估算阅读量。

### 附录 F · 选题清单

```markdown
# 附录 F · 选题清单

### 01 · <选题标题>

- 角度 / 为什么现在 / 用哪条证据 / 目标平台 / 钩子方向 / 形式 / 难度 / 我的优势 / 风险
```

### 附录 G · 内容结构模板

```markdown
# 附录 G · 内容结构模板

## 模板一 · <名字>

- 来源 / 适用 / 骨架 / 句子模板 / 失败条件
```

## 三、md 与 epub 的分工

| 格式 | 位置 | 用途 | 排版 |
| --- | --- | --- | --- |
| 合并 md | `20-输出/<人物>·思维操作系统2.0（全书）.md` | Obsidian 检索、复制原话、做内容 | 保留表格、标题层级、可点击链接 |
| epub | `<输出目录>/<人物>·思维操作系统2.0（阅读版）.epub` | 微信读书通读 | 表格转卡片、目录三层、手机排版 |

两者由同一个源文件生成，不要分别维护。改内容只改源文件，然后重跑构建。

## 四、构建命令

```bash
python3 ~/.claude/skills/tome-portrait/scripts/make_book.py \
  --project "<项目目录>" \
  --title "<人物>·思维操作系统 2.0" \
  --subtitle "<一句话副标题>" \
  --author "<人物>" \
  --editor "<整理者>" \
  --cover "<项目目录>/assets/cover.png"   # 不给则自动生成

# 或直接用 tome-book skill
python3 ~/.claude/skills/tome-book/scripts/build_book.py \
  --project "<项目目录>" \
  --title "<人物>·思维操作系统 2.0" \
  --out "<输出目录>/<人物>·思维操作系统2.0（阅读版）.epub" \
  --md-out "<项目>/20-输出/<人物>·思维操作系统2.0（全书）.md"
```

如果 `00-收集/` 是微信文章标题而不是 `NNN：` 集号，`--project` 自动识别会漏掉全部文章；先按 `tome-book/references/wechat-book.md` staging，再用 `--config book.json` 构建。

构建会做：

1. 合并总纲 + 逐集 + 外部 + 传播案例 + 附录 F/G。
2. 去 frontmatter、`---` → `***`、H1 标准化、标题前补空行。
3. 口播稿分段、时间戳降噪、重复观点删除。
4. pandoc 生成 epub，再后处理：表格转卡片、URL 换行、viewport、扉页、篇章页、nav/NCX、OPF、CSS。
5. 输出合并 md 和 epub。
6. 跑验收。

## 五、链接规则

- 每篇开头放原视频 / 原始来源链接；只链到页面，不链时间戳。
- 外部素材的每个关键事实尽量带 URL；URL 太长时用 Markdown 链接文字，不要直接裸露长链接。
- epub 里链接可点；微信读书会保留外链。

## 六、索引

成书后生成两个索引，放 `20-输出/`：

### 案例索引

```markdown
| C 编号 | 案例 | 一句话 | 支撑什么 | 可复用场景 | 来源 |
| --- | --- | --- | --- | --- | --- |
```

### 金句索引

```markdown
| Q 编号 | 引语 | 主题 | 来源（集号 / 时间戳） | 链接 |
| --- | --- | --- | --- | --- |
```

- 索引由模型从已结构化的 md 中抽取；不要重新读原始字幕。
- 索引里的 ID 必须和正文一致。
- 案例索引按主题分组；金句索引按主题分组，不按时间。

## 七、验收

- [ ] 章节数 = 总纲 1 + 逐集 N + 外部 N + 传播 N + 附录 F 1 + 附录 G 1（没有的项不计）。
- [ ] 目录三层：篇 → 章 → 总纲内小节；附录 F、G 在顶层，顺序正确。
- [ ] 封面、扉页、篇章页都在 spine 里。
- [ ] 0 张表格（epub）；表格已转卡片或定义行。
- [ ] 0 个 `ch*.xhtml` 形式的 `<title>`。
- [ ] 0 个失效的 nav / NCX / 书内目录链接。
- [ ] 所有 XML 解析 0 错误。
- [ ] `mimetype` 是 zip 第一条且 store 模式。
- [ ] 合并 md 的标题层级、链接、frontmatter 都正确。
- [ ] 案例索引、金句索引的 ID 与正文一致。

## 八、常见坑

- pandoc 把独立 `---` 当表格分隔线，吞掉后续章节；构建时换成 `***`。
- `[MM:SS] 文本` 被 pandoc 误判成表格；构建时转成引用块或受控段落。
- 章节 H1 不统一；用文件名 / 章节标题覆盖。
- 目录被每篇的 6 个固定小节撑爆；逐集篇只保留章标题，总纲保留到 H3。
- 封面用 pandoc 默认的 SVG 包装，部分阅读器渲染异常；换成纯 `<img>`。
- 多个附录时，构建器只把「附录」开头的章节提升为顶层；标题写成 `附录 G · ……`，否则会嵌进上一篇。
- 正文裸 `<`（如微信的 `<滑动查看下一张图片>`）会让 pandoc 生成 mismatched tag；先换中文括号，再统一转 `&lt;`。
- 微信读书会覆盖字体、行距、背景；结构、目录、分段、卡片不会被覆盖。
